**Status:** Static review of the unpacked `stick-figure-windows/` directory only. **Not a clearance to execute or integrate.** The requested `stick-figure-windows-v2.zip` was not found in the workspace, so ZIP integrity, archive-member safety, and identity between the ZIP and this directory could not be verified. No installer, package manager, renderer, Python tool, or network service was run.

## Executive decision

**Candidate: promising for controlled evaluation, not integration-ready.** Existing code and docs show a code-driven 1080×1920 Canvas/Playwright renderer, 30 fps frame generation, FFmpeg mux, English Kokoro voice generation, word-alignment, and subtitle timing. The sample reel is only 37.4 seconds; docs describe the skill as 30–45 seconds. Indonesian speech and alignment are not supported by the included default voice/aligner as configured. Generated JavaScript is executable, scripts have broad filesystem/process access, and the installer downloads and installs software/models. A Rust adapter may supervise a *trusted, audited, pinned* renderer as a subprocess, but ordinary process supervision is not a sandbox.

**Recommendation:** obtain the exact ZIP and provenance, verify its digest and inventory, complete dependency/model/license review, then seek explicit approval for a disposable, network-restricted smoke. Do not run the included installer or accept generated code in Scenivox. Prefer validated declarative scene input rendered by reviewed code.

## Structure, dependencies, and execution surface

Observed files: `skills/stick-figure/SKILL.md`; `engine/make.sh`; Python tools `tts_kokoro.py`, `tts_elevenlabs.py`, `align.py`; Node `render.js`; `engine/template/{script.json,captions.json,audio.py,web/*}`; `kit/package.json` and `package-lock.json`; Windows installer/wrappers and `LICENSE`.

- `SKILL.md:25-29,39-51` documents Python 3.9+, Node, FFmpeg, Playwright/Chromium, Python voice/alignment models, a shell build, and manual per-reel editing of JS shot code. The actual Windows installer expects Python 3.12, Git Bash and winget (`install-windows.sh:1-5,16,23-24`). This difference needs a tested, pinned compatibility matrix.
- Node kit pins Playwright 1.49.1 and Three 0.169.0, plus Montserrat (`kit/package.json:5-9`; `kit/package-lock.json:34-68`). Playwright requires Node >=18 (`package-lock.json:45-47`). `fsevents` has an install script but is marked optional and macOS-only (`package-lock.json:20-32`). No Node installation was run; transitives and their install hooks remain unreviewed.
- Installer installs Python, FFmpeg and Node with winget (`install-windows.sh:25-52`); runs `npm install` and `npx playwright install chromium` (`:67-76`); pip-installs packages (`:78-84`); downloads Kokoro and Parakeet models over HTTPS and extracts a tar archive (`:85-92`). Thus it mutates the host, needs network, and trusts package/model endpoints and an archive extraction path. Do not run it as a smoke test.
- Build script runs Python, Node and FFmpeg, starts parallel render workers, writes/replaces reel artifacts, and muxes final media (`engine/make.sh:24-61`). It is Bash-centric; Windows support depends on Git Bash/Cygwin path handling and an installer-generated `kitpath.txt` (`make.sh:11-20,52-54`; `install-windows.sh:54-65`). Native Windows compatibility is unverified.
- Renderer uses Playwright Chromium with `--allow-file-access-from-files`, opens a local `file://` page and spawns FFmpeg (`engine/tools/render.js:3-13,30-37`). This is a local-file trust boundary, not isolation. Renderer assumes project-controlled JS and executable `ffmpeg` on PATH.
- Alignment and audio scripts read/write relative to the current directory (`tools/align.py:22-23,49-63`; `template/audio.py:5`). The ElevenLabs script reads a reel `.env`, reads the API key from process environment, and makes a paid external request (`tools/tts_elevenlabs.py:1-6,10-18,34-42`). A Scenivox adapter must not expose project files/secrets or enable this network path implicitly.
- The bundle guide recommends bypassing Windows SmartScreen and approving UAC when installing (`BACA-DULU.md:28-36`); do not follow that guidance for audit/smoke.
- Security posture: treat `shots.js`, `audio.py`, installer/package lifecycle code, and generated artifacts as untrusted executable content. The audited files show arbitrary Python/JS execution and filesystem writes. No demonstrated OS-level sandbox, resource cap, network restriction, or secret isolation. Rust `Command` with argv, restricted CWD/environment, path containment, timeout, process-tree cleanup, output caps and single-job scheduling are necessary controls but are not a complete sandbox. Fail closed for arbitrary AI-generated scripts unless a separately reviewed isolation boundary is available.

2. **Provenance and license scope:** confirm upstream commit/tag and correspondence; review all included notices, code, package transitive licenses, fonts, model weights/voice rights and any test media. Preserve MIT/OFL notices if redistributing where required. Ask project owner to decide packaging/distribution; no project-wide license is chosen (`README.md:35-36`).
3. **Safe execution boundary:** do not run the included installer or arbitrary generated `shots.js`/`audio.py` on the host. Decide whether a disposable VM/container with no secrets, read-only source, isolated output, disabled network, resource/time limits and process cleanup is available. If not, defer executable smoke; static-only is safer.
4. **Runtime reproducibility and Windows:** verify OS, exact Python/Node/FFmpeg/Chromium versions, pinned Python dependency set (none supplied as a lock file in observed tree), model hashes/origins, paths and child-process cleanup. No environment was bootstrapped or exercised.
5. **Product fit:** obtain an approved Indonesian voice sample/rights and budget if using a paid provider; validate recognizer support and word timing on Indonesian. Establish 60 s script/shot/audio behavior. The current sample is English and 37.4 s.
6. **Adapter contract:** define JSON input and output with validated scene data, explicit audio/timing and capability limits; avoid writing executable code from model/user text. Require output manifests, hashes and measured media checks before job success.
